# GameNewsUnified：TraeWork 后端交接

更新时间：2026-08-27。前端与只读接口层已由 Codex 完成；TraeWork 仅接管采集、规则、调度、飞书、输出与数据迁移。

## 已完成，不要重做

- React/Vite 前端：[src/App.jsx](../src/App.jsx)
- 统一样式：[src/unified.css](../src/unified.css)，继承 NewgameWiki 的设计系统
- 服务与只读接口：[server/api-server.mjs](../server/api-server.mjs)
- 统一数据库：[data/game-news-unified.sqlite](../data/game-news-unified.sqlite)
- 网站入口：`http://127.0.0.1:64500/`
- 管理页：来源管理、游戏管理、定时任务、运行日志

## 约束

- 不重做前端，不改 `src/App.jsx` 和 `src/unified.css` 的页面结构。
- 不删除旧项目数据库、旧输出、飞书历史；迁移只增不删。
- 不覆盖人工评级，不把采集日期当业务日期。
- 不读取、提交或写入密钥文件；真实机器人发送必须先 dry-run，再由用户明确授权。
- 不把本地图片缓存当主数据。文章保留远程图片 URL；仅输出 HTML/PNG 时缓存必要素材，并设计可清理策略。

## 目标工作流

```text
TapTap / 好游快爆 / 小七 / Steam / 端游资讯
  → 列表采集 + 必要详情补齐 + 远程图片 URL
  → 清洗、业务日期提取、来源内去重
  → 跨平台事件合并
  → GameNewsUnified SQLite
  → 已完成的资讯网站和后台
  → 简讯 / 海报 / 周报输出
  → 飞书多维表 + 两类机器人
```

## 分阶段实施

### P1：数据适配与接口稳定

- 补齐前端所需文章字段：缩略图、清洗摘要、业务日期、原文链接、来源、评分。
- 新增 `/api/admin/tasks`，让定时任务页从真实任务配置读取。
- 建立 API 合约测试；空值需明确显示“待补”，不能伪造状态。

验收：前端不改代码即可显示真实数据，`npm run build` 和 `npm test` 通过。

### P2：采集器迁入

- TapTap：新游日历 + 活动详情。
- 好游快爆：即将上线 / 即将测试作为新游；即将更新作为活动。
- 小七：预约新游、折扣、预约量、厂商、标签。
- Steam 与端游资讯：保留目前统一库口径，新增来源记录。
- 详情只对新增记录或详情缺失记录抓取。

验收：每个平台至少一个固定回归样本，检查游戏名、日期、厂商、评论/预约量、原文链接、图片。

### P3：清洗与去重

- 游戏名：去除“官服、预约、预下载、活动后缀”；保留“体验服”等正式区分。
- 好游快爆更新动态：仅取第一条当前更新，其余为历史，禁止重复补入。
- 时间：活动开始/更新日期与入库时间分离。
- 跨平台：同游戏 + 日期接近 + 标题关键词重叠。
- 飞书监控偏好：新游优先 TapTap，活动优先好游快爆；不得静默改变今日简讯或海报来源选择。
- 人工评级优先于自动评级。

验收：新游与活动不串表；重复活动不会因历史动态反复新增。

### P4：调度和运行记录

- 将 `server/tasks/scheduler.mjs` 的任务定义写入可读取的任务配置层。
- 新游/活动监控：每 1 小时。
- 今日简讯海报：每日 09:30。
- 周报：周一 09:00，统计过去 14 天。
- 任务结果写 `crawl_runs` / `publication_runs`；前端只展示和调用 API，不直接运行系统命令。

验收：后台显示真实的频率、下次执行、上次结果；失败原因可查。

### P5：飞书同步和机器人

- 飞书新游、活动表按业务日期、评级、评分排序；仅 S/A 发送提醒。
- 两个机器人独立：海报推送、新游/活动提醒。
- 发送指纹防重；人工评级、历史记录不可被爬虫覆盖。
- 首次仅 dry-run，报告预发送内容；真实发送需用户单独确认。

验收：同一事件不会跨平台重复发送；新游与活动分别发送；飞书保留历史。

### P6：输出生成

- 消费统一库生成今日简讯、海报、周报。
- 输出写入 `output/brief-archive`、`output/poster-archive`、`output/weekly-poster-archive`。
- 每次生成都写 `publication_runs`，网站可直接访问输出 HTML。

验收：HTML、PNG（如配置）和数据库运行记录三者一致。

## 迁移验证与切换

1. 先备份统一库和旧项目数据库。
2. 双跑 3 天：旧任务和统一任务并行，只比较结果，不停旧任务、不重复发送机器人消息。
3. 对比来源条数、去重率、业务日期、图片、原文、评级、飞书新增记录。
4. 用户确认后，再关闭旧项目对应任务；旧库留档，不删除。
5. 清理缓存前单独统计大小、列出目录、获得确认后再执行。
