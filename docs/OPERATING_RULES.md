# GameNews 运行与优化规则

## 允许的改动边界

### 默认允许

- 修改 `src/` 页面、组件和 CSS。
- 修改 `server/crawler/` 的过滤、解析、限流和图片处理逻辑。
- 增加回归脚本和文档。
- 调整固定端口配置，但必须同步 Vite proxy、后端 CORS 和 preview 命令。

### 需要先确认

- 修改 `server/database.js` 的表结构、迁移、字段语义。
- 批量清理、覆盖或删除 `data/game-news-hub.sqlite`、JSON、图片和日志。
- 安装新依赖，尤其是会改变抓取方式、浏览器运行时或生产包体积的依赖。
- 修改定时任务时间、自动详情抓取范围或 Firecrawl 每日额度。

### 禁止

- 将 API 密钥写入源码、README、日志或测试数据。
- 把未验证的真实抓取数量写成稳定指标。
- 用爬虫修复掩盖前端状态问题，或用前端改动绕过服务端失败。
- 对未授权站点进行扩展扫描。

## 前端规则

1. 保持现有 hash 路由：`#/dash`、`#/feed`、`#/brief`。
2. 页面名称使用当前产品语言：今日简讯、抓取资讯、简讯编辑。
3. API 调用优先放在 `src/services/api.js`，不在组件内重复拼接后端地址。
4. 主题使用 `data-theme` 和 CSS 变量，不能只修亮色截图。
5. 资讯工作台优先信息密度、扫描效率和状态反馈，不添加营销式首屏。
6. 所有加载、空数据、失败、禁用、重新生成状态都要可见。
7. 修改 UI 后至少执行 `npm run build`；涉及布局时补做桌面和 390px 移动端检查。

## 后端规则

1. API 错误使用 `{ ok: false, message }`，成功响应保留 `{ ok: true, ... }`。
2. 单个来源、文章或图片失败应隔离，批量任务继续处理其他项目。
3. 文章 ID 使用来源和 URL 生成的稳定 ID，不能用随机 ID 替代去重键。
4. 详情抓取写回 `paragraphs/facts/images_json/quality/game_match/diagnostic` 时保持 JSON 可解析。
5. 所有外部请求必须有超时；Firecrawl 必须有并发、URL 去重和额度边界。
6. 修改服务端后检查 `http://127.0.0.1:64424/api/health`。

## 爬虫与清洗规则

1. 候选阶段只保存标题、游戏名、来源、分类、详情 URL、初始分数等基础字段。
2. 用户手动流程必须是：候选 → 勾选 → 估算 → 确认 → 详情。
3. 列表过滤和评分是两层不同规则：过滤器决定是否保留，评分决定排序，不能混用。
4. 论坛帖、评分卡、排行、推荐、抽奖、礼包、兑换码、广告和下载导流优先排除。
5. 正文必须经过长度、广告词、游戏匹配和事件信号判断，再标记 `verified/needs_review/low_quality`。
6. 清洗脚本执行前先备份 SQLite，并打印影响行数；禁止把全量数据更新脚本挂到普通启动命令。
7. 每次过滤器变更至少补一条正样本和一条负样本到 `scripts/crawler-regression.mjs`。

## 浏览器验证重点

主题持久化、今日简讯分类导航、抓取资讯的两阶段操作、简讯编辑的历史/拖拽/保存、爬虫监控状态刷新和来源链接，以及 390px 移动端无横向溢出。

## 推荐验证顺序

```text
静态检查 -> npm run build -> npm run check:crawler
-> 启动服务 -> /api/health -> 浏览器页面 -> 真实站点小样本
-> 再考虑批量抓取或清洗脚本
```

## 后续个人方案建议模板

在重新设计前，先写清楚四件事：

1. 目标用户要完成的最短操作路径。
2. 候选、详情、确认、简讯之间的状态机。
3. 哪些数据需要长期保留，哪些只是缓存或输出物。
4. 自动任务和人工任务是否共用数据池、评分和失败重试策略。

## 数据保留与简讯归档

- 文章数据窗口为最近 48 小时；流水线执行时通过 `cleanupOldArticles(48)` 清理超过窗口的文章。
- 本次不主动删除已有历史文章；爬虫暂停维护期间也不运行清理流水线，恢复后按 48 小时规则执行。
- `daily` 简讯不随文章清理删除，数据库记录保留；文件按日期写入 `data/brief-archive/daily/YYYY-MM-DD.json`。
- 早报、晚报和周报也会写入对应日期归档目录，同时保留当前输出文件作为最新指针。
- 归档读取接口为 `GET /api/brief/archive/:slot` 和 `GET /api/brief/archive/:slot/:date`。
