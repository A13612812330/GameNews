## 2. 立项方案

### 2.1 项目定位
GameNews 是面向手游分发和内容运营人员的中文游戏资讯中台。它把游戏来源采集、清洗、分类、评分、人工评级、飞书同步和日报/周报输出串成一条运营工作流。

### 2.2 核心目标
1. 聚合手游、Steam 与端游资讯。
2. 识别新游、测试、上线、版本更新、活动与联动。
3. 通过去重、机器评分和飞书人工评级筛选高价值内容。
4. 输出今日简讯、日报海报、周报海报。
5. 同步飞书游戏库并只推送新增 S/A 级提醒。
6. 通过私有 GitHub 保存代码和正式海报，支持其他电脑恢复部署。

### 2.3 非目标
- 不作为通用互联网爬虫。
- 不执行游戏自动发布、商店上架或账号操作。
- 不上传真实密钥、数据库、缓存、日志和备份到 GitHub。
- 不把飞书作为唯一数据存储。
- 不长期保存全部正文图片。

### 2.4 建议验收标准
- `64423 / 64424 / 64425` 按职责正常，`64424/api/health` 返回正常。
- 六个采集源可独立执行，单源失败隔离。
- RAW、Dashboard、简讯、海报字段可追溯。
- 同类型日报/周报同日只成功投递一次。
- 新增 S/A 提醒，B/C 不提醒。
- 活跃数据 7 天、周报快照 30 天、轻量 JSON 长期留档。
- GitHub 不含敏感配置、数据库、缓存、日志和备份。
- `npm run build`、`npm run check:crawler` 通过；390px 页面无横向溢出。
- 飞书人工评级下一轮同步后回写并影响事件评级。

## 7. 清洗、去重和评分

### 7.1 去重
- URL 唯一键去重。
- 游戏名 + 标题内容归一键去重。
- 去标点和部分状态词后比较。
- 当前 `deduper.js` 会移除游戏名末尾的“官服 / 测试服 / 正式服”。

**规则冲突：** 既有业务要求体验服/测试服独立；当前“测试服”归一可能误合并，列为 P1。

### 7.2 自动分数
- 基础分 50。
- 新游、上线、测试、版本、活动、书名号、官方、明确日期和手游来源加分。
- TapTap 新品榜、热榜和重点 IP 加权。
- 论坛、排行合集、抽奖、折扣、纯英文等扣分。
- 最终限制在 10–95。

重点 IP 包括黑神话、宝可梦、奥特曼、西游、斗罗、原神、崩坏、王者荣耀、燕云十六声、三角洲行动、鸣潮、明日方舟、逆水寒、和平精英等。

### 7.3 分数与评级
- `articles.score` 用于资讯排序和筛选。
- 飞书“游戏评级”用于人工评级回写。
- 每轮先读人工评级，再同步事件。
- 新增 S/A 才提醒，B/C 只入库。

### 9.2 增量流程
1. 从“游戏评级”表读取人工评级并回写。
2. 将当前有效新游/活动增量写入主表。
3. 不删除、不重建、不物理重排飞书历史记录。
4. 只对本轮新增 S/A 发送提醒。
5. 新游红色、活动橙色，分消息发送。
6. 活动可带首图；好游快爆文案按 `，`、`；`、`!` 等分行。
7. 单消息最多 8 条，更多内容引导查看飞书表。
8. 通知失败不回滚表写入和本地采集。
