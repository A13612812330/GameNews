4. 数据迁移内容与字段规则

目标必须迁入关键规则验收
资讯与事件文章正文、图片清单、来源 URL、业务日期、清洗标题/游戏名、评分、人工评级、选择状态文章 ID 不可仅用游戏名；事件去重采用游戏 + 日期桶 + 分类 + 标题语义；保留多来源关系。随机抽 20 条：原文、清洗字段、业务日期与手工评级一致。
简讯/海报/周报历史 HTML、条目、模板、生成时间、归档/回收站状态、下载文件映射输出文件使用日期命名；历史不因日常清理消失；周报读取过去 14 天留档。各打开 3 个历史文件；回收站恢复一次；生成一次新 HTML。
RAW 与运行审计必要的 crawl_runs、失败记录、规则快照、RAW 产物元数据不建议无脑导入所有原始 HTML；保留可审计范围与近期开关。运行一次抓取，能看到来源、发现/新增、失败原因和 RAW 链接。
图片与缓存文章/海报/简讯实际引用的本地图片；外链原 URL仅复制被引用的 /crawler-assets/；外链可失败时使用统一代理/本地副本策略。抽样 TapTap、好游快爆、Steam、海报各 5 条，图片可显示。
飞书文档与评级游戏评级、人工说明、平台、事件记录、入库时间、来源链接人工评级永远覆盖自动评分；新游同游戏优先 TapTap，活动同事件优先好游快爆。人工调一条评级后，同游戏后续事件与排序同步更新。

阶段任务允许写入退出条件

P1 差异对账对文章、事件、简讯、海报、运行记录、RAW、图片引用做数量/字段差异表。报告文件。每项有“已迁/缺失/不迁原因”。
P2 数据补迁扩展幂等迁移脚本，补迁选择、brief_items、运行审计、必要 RAW 元数据。仅统一库；写 migration_logs。dry-run 与实迁数量一致；重复运行不新增业务重复。
P3 引用资产与输出建立 assets 清单；复制引用图片；迁移 HTML/PNG 输出和归档索引；接入图片代理。统一项目 data/assets、output。抽样图片/历史文件在统一项目可打开。
P4 核心功能迁移迁移 Feed、Brief、Crawler Monitor 的真实 API 和 UI；实现选择持久化、回收站、RAW。统一项目前后端、测试。完整跑通“抓取→选择→编辑/海报→归档”。
P5 飞书与定时任务迁入文档同步、两个机器人、日/周海报任务；发布默认关闭，先 dry-run。统一库通知/投递表；外部发送仅经明确确认。两种机器人分别通过模拟消息和指纹防重测试。
P6 连续双跑旧项目与统一项目并行：连续 3 个日任务 + 1 个周报。两边各自输出，不互相覆盖。无 P0/P1 差异；报告可审核。
P7 正式切换先切新输出/机器人，再观察 24 小时，最后暂停旧任务。计划任务与服务状态。可回滚；新任务稳定；用户确认暂停旧任务。
P8 缓存清理稳定 14 天后扫描旧缓存，生成待删除清单并等待人工确认。无，直到用户确认删除。删除后仍能打开所有当前引用资产。

6. 前端实施要求（避免再出现“页面像功能但不可用”）

公开站顶部导航，只保留 5 项

  • 资讯首页
  • 新游与活动
  • Steam 新游
  • 简讯海报
  • 管理后台

读者不应看到抓取、来源、飞书和运行日志；这些只在管理后台出现。

后台侧栏，只保留 4 项

  • 运营概览：待办、来源状态和关键统计。
  • 内容审核：分组、筛选、勾选、详情、来源原文、人工评级。
  • 简讯出品：编辑器、生成、预览、下载、历史与回收站。
  • 爬虫监控：来源状态、手动抓取、RAW 验收、运行日志。
任何“生成海报 / 导出 HTML / 发送飞书”按钮，必须调用真实 API 并在成功后提供可打开/下载的产物；功能未迁完前必须显示迁移状态，不能伪造完成。

7. 飞书、机器人与定时任务迁移

任务频率/触发输出去重与安全要求
新游/活动监控每小时采集完成后，仅处理本轮新增飞书文档记录；S/A 新游、活动分两条消息发送同游戏 + 事件日期 + 标题关键词；同游戏新游优先 TapTap，活动优先好游快爆；发送指纹入库。
每日海报每日 09:30（当前约定，切换前再确认）今日海报 HTML/PNG + 飞书消息生成成功才发送；归档文件以日期命名；消息与文件状态分别记录。
周报海报每周一 09:00（当前约定，切换前再确认）过去 14 天周报 HTML/PNG + 链接具体日期，不使用“今日/昨天”；Steam、端游、活动按各自规则读取。
RAW 验收每次抓取完成后RAW_ARTICLES.html / JSON与抓取资讯采用同一规则投影；本地图片走静态资产服务，远程防盗链图走统一代理。
凭据边界：不读取、不复制、不打印旧项目 .env 或密钥。TraeWork 只提供环境变量名称与配置模板；由用户在新服务运行环境中填入。真实发送必须在用户明确授权后开启 --publish。

8. 验收清单

  • 旧项目数据库的哈希与记录数未被迁移过程改变。
  • 统一库可重复运行迁移，第二次不产生重复 articles/events/brief_items/assets。
  • 固定回归案例：好游快爆游戏名清洗、TapTap/好游跨平台合并、活动业务日期、人工评级覆盖均通过。
  • 抓取资讯：选择 3 条后刷新页面，选择状态仍在；进入简讯编辑后条目一致。
  • 简讯：生成 HTML、预览、下载、归档、移入/恢复回收站均可用。
  • 海报：默认使用今日条目；生成后给出打开和下载入口；本地/远程图片至少抽样 20 张正常显示。
  • 周报：过去 14 天；重点新游、活动、Steam、端游资讯规则正确；无数据区不渲染。
  • RAW：与抓取资讯共享同一清洗、日期和去重口径；可打开且图片可显示。
  • 飞书：文档写前校验字段；人工评级同步；机器人模拟消息分新游/活动；同指纹不重复发送。
  • 双跑：连续 3 个日任务 + 1 周报的差异报告为零个阻塞项。
  • 浏览器：桌面与 390px 下导航清晰、无横向溢出、控制台无错误。
  • 切换后 24 小时：新服务正常、旧任务仍可恢复；用户确认后才暂停旧任务。

9. 明确禁止事项

  • 不得整包复制 GameNews/node_modules、缓存、临时输出或超过数十 GB 的 crawler-assets。
  • 不得先停止 GameNews 的任务、飞书机器人或本地服务。
  • 不得用“游戏名”作为唯一主键；Steam 仍以 AppID 为唯一主键。
  • 不得覆盖人工评级、来源链接、业务日期、原文内容或历史归档。
  • 不得把实时、历史、演示 Steam 数据混排。
  • 不得把未实现的生成、下载、发送按钮显示为可用。
